# Public Repository Boundary

The public GitHub repository should be created as a clean snapshot near release time, not by publishing the full private development history.

## Include

- `src/`
- `public/`
- `docs/`
- `scripts/`
- `README.md`
- `ROADMAP.md`
- `CHANGELOG.md`
- `CONTRIBUTING.md`
- `LICENSE.md`
- `.github/ISSUE_TEMPLATE/`
- `.gitignore`
- `package.json`
- `package-lock.json`
- `tsconfig.json`
- `vite.config.ts`

## Exclude

- `.git/` private history
- `.agents/`
- `.codex/`
- `node_modules/`
- `dist/` unless attaching a separate built release zip. `dist` is generated by `npm run build` and should not be edited by hand.
- API keys and `.env` files
- local extension storage dumps
- subtitles, transcripts, translations, screenshots, audio snippets, and Anki packages
- LLM debug records, raw prompts from private testing, and agent/chat transcripts

## Candidate Copy Check

Before initializing the final public repo, run:

```sh
npm run public:check
```

The check is intentionally conservative. If it fails, either remove the flagged local/private artifact or update this document with a clear reason why that file is safe to publish.

## Public Snapshot Helper

From the private workspace, a safe candidate copy can be prepared with:

```sh
npm run public:snapshot -- ../ylang-public-candidate
```

The target directory must be empty. The script copies only the public include list and does not initialize git or publish anything.

## Public Init Procedure

1. Create a new empty directory outside the private workspace.
2. Copy only the included paths above.
3. Run `npm install`.
4. Run `npm run typecheck`, `npm run build`, `npm run release:check`, and `npm run public:check`.
5. Initialize git in the clean directory.
6. Make the first public commit from that clean snapshot.

Do not copy private commit history into the public repository.
